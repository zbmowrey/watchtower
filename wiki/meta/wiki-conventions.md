# Wiki Conventions

This wiki is the repo's **on-disk, permanent memory**. It is a Karpathy-style
LLM wiki: a folder of plain-markdown *entity pages* — one concept per file —
interlinked with wiki links. Retrieval is via the [[wiki-tool]] (`bin/wiki`),
not by dumping the whole corpus into context, so it stays fast as it grows.

## One concept per page

Each file is a single entity: a project, an infra system, a stack tool, a
pattern, a gotcha. If a page starts covering two things, split it and link them.

## Frontmatter contract (required)

Every page MUST begin with a frontmatter block. `bin/wiki lint` enforces it.

```yaml
---
title: Human Readable Title
description: One-line summary — shown in the search index, so make it useful.
tags: [laravel, deploy, k8s]
type: project          # must match the page's top-level domain directory
status: normative      # optional: normative | reference | living
updated: 2026-06-13
related: [some-slug, another-slug]   # optional; slugs of related pages
---
```

- **Required:** `title`, `description`, `tags`, `type`.
- **`type`** is aligned to the page's **top-level domain directory** (directory ==
  domain) — one of `project | infra | stack | security | standard | log | reference
  | meta`. `bin/wiki lint --hubs` enforces the match (`wiki/security/x.md` ⇒
  `type: security`). This keeps `--type` a useful filter as the corpus grows.
- **`status`** — optional volatility marker: `normative` (a rule of record),
  `reference` (durable background), or `living` (dated/churny — status, logs,
  rollout, registers). **Living pages live under `wiki/logs/`** and are excluded
  from normative reading. See *Law vs news* below.
- **`updated`** — ISO date; bump it when you revise a page.
- **`related`** — optional list of page slugs; the tool treats these as links
  too (followed during `inject --depth`).

## Linking

- Inline syntax is a double-bracket page link, optionally with display text. The slug is the
  filename without `.md` (or the slugified title) — e.g. `acme`,
  `deploy-flow`.
- Standard markdown links to other `.md` files are followed too.
- **Hubs are path-addressed, not slug-addressed**: a `some-dir` wikilink does NOT resolve
  to `some-dir/_index.md`. Link a hub with a markdown path
  (`[the manual](../stack/laravel-architecture/_index.md)`) or link a representative leaf.
- Link liberally. A forward link to a page that doesn't exist yet is fine — it
  marks something worth writing later.

## Directory layout — directory == domain

Each top-level directory is a **domain**; a page's `type` matches its domain.

```
wiki/
  _index.md                 ROOT hub — index of the domain hubs (generated)
  meta/                     how the wiki/tooling itself works (conventions, tool)
  projects/                 one page per project (acme, ...); the roster lives outside the wiki
  infra/                    k8s, deploy flow, CI, local ports
  stack/                    shared tech (laravel-sail, pest, inertia-react, arch manual)
  security/                 the security & compliance corpus
  standards/                the engineering standard (the rule, philosophy, cquality)
  logs/                     dated 'news': convergence logs, backlogs, registers (status: living)
  reference/                external research / evaluations
```

Directory is organizational *and* drives `type`; search and links still cut across
it freely.

## Hubs are generated, never hand-maintained

Every domain directory has an `_index.md` **hub**. A hub's navigation list is
**generated** by `bin/wiki index` from its directory's leaf frontmatter — so it
can't drift from what's on disk. Keep any hand-written narrative **above** the
markers; everything between them is rewritten:

```
<!-- shards:begin -->
<!-- generated by `bin/wiki index` — do not hand-edit between the markers -->
- 📁 [Sub Hub](subdir/_index.md) — its description
- `<leaf-slug>` — its description
<!-- shards:end -->
```

A directory that grows past ~12 leaves (or a project past ~3 sub-pages) is promoted
to its own sub-directory with an `_index.md` (the `stack/laravel-architecture/`
pattern). `bin/wiki lint --hubs` fails on a populated directory with no hub.

## Law vs news

Timeless rules ("law") and dated status ("news") never share a page. News — PR
numbers, rollout dates, per-app convergence, risk registers — is `status: living`
and lives under `wiki/logs/`. A normative page links to the living ledger ("current
status → convergence log") instead of carrying the dates itself, so it can't go
stale on a status change.

## Self-organizing rules (the mandate)

The repo-wide self-maintenance mandate — standing authority to tend without asking,
search-before-web, write-back, correct-in-place, single-source, law-vs-news — is the
**[[tending-the-garden]]** charter. It governs the whole repo, not just the wiki; read
it. The wiki-specific application of that mandate:

1. **One concept per page; link generously.** If a page starts covering two things,
   split it and link them.
2. **Correct in place** and bump `updated:` — never append "actually, now it's X".
3. **Keep frontmatter valid** (`bin/wiki lint`) and **hubs honest**
   (`bin/wiki lint --hubs`); regenerate navigation with `bin/wiki index`.
4. **Fix tooling docs where they live.** If a command's syntax in CLAUDE.md or a page
   is wrong, correct it at the source.

See also: [[wiki-tool]] for the search/inject/lint/index commands.
