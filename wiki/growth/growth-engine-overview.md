# Growth Engine — overview & corpus map

Use this page to choose the next growth action. Use the linked shard pages for the exact execution checklist.

## Core Model

- Start with positioning.
- Measure the funnel before changing it.
- Find the weakest stage against benchmark and first-party baseline.
- Fix one stage per cycle.
- Re-measure before opening the next stage.
- Keep every fact in its owner page; link instead of duplicating.

## Sequence For A New Product

1. Write the positioning brief.
2. Install analytics and revenue tracking.
3. Ship or audit one money page.
4. Define and instrument activation.
5. Pick one acquisition lane.
6. Capture non-buyers.
7. Add retention work.
8. Add referral only after retention readiness.

## Daily / Weekly / Monthly / Quarterly

- Daily: check pulse dashboard and threshold alerts.
- Weekly: review funnel stage rates, activation, SEO queries, experiments, and channel gates.
- Monthly: review MRR movement, cohorts, content decay, channel performance, and the next constraint.
- Quarterly: rerun positioning, keyword/topic research, retention/NRR, referral readiness, and roadmap priority.

## First 7 Days

- New SaaS: positioning, analytics, one money page, activation, one acquisition lane.
- Local business: Google Business Profile, homepage/mobile conversion path, call/form tracking, review trigger, LocalBusiness schema.
- Relaunch: baseline snapshot, data-quality check, constraint selection, top-page audit, migration runbook if URLs change.

## First 30 Days

- Choose one constraint.
- Ship one measurable improvement per week.
- Keep the acquisition lane narrow.
- Use [[product-growth-roadmap-template]] for project-specific execution.
- Use [[growth-principles-runbook]] for compressed rules across all shards.

## Avoid

- Opening multiple channels before measurement works.
- Buying traffic before the money path converts.
- Optimizing a stage already near benchmark while another leaks.
- Changing pages before checking instrumentation, seasonality, bots, and source mix.
- Copying facts across pages instead of linking to owners.
