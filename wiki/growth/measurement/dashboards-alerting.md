# KPI Trees, Dashboards & Alerting

Use this to turn metrics into operating decisions.

## Do

- Build a KPI tree from revenue to funnel stages.
- Create daily, weekly, and monthly dashboard views.
- Define thresholds before alerts fire.
- Review one constraint per week.
- Triage anomalies before changing strategy.
- Keep the same monthly report format.

## When

- After analytics and revenue pipeline are installed.
- Before recurring growth reviews.
- Before paid spend or channel scaling.
- After major tracking, pricing, launch, or migration changes.

## How

1. Pick north-star and revenue metrics.
2. Map input metrics to each funnel stage.
3. Create daily pulse: traffic, signups/leads, activation, revenue, errors, alerts.
4. Create weekly review: stage conversion, channel, experiments, activation, SEO.
5. Create monthly report: MRR movement, cohorts, churn, channel, content, next constraint.
6. Set thresholds using baseline and business impact.
7. Route alerts to an owner with a first action.

## Watch

- Instrumentation bugs.
- Bots and spam.
- Seasonality.
- Source-mix shifts.
- Release regressions.
- Payment failures.
- Broken forms or checkout.
- SEO drops by page type and query group.

## Avoid

- Alerting on noise.
- Changing product from a single-day metric move.
- Reviewing every metric equally.
- Mixing daily pulse and strategic review.
- Letting dashboards exist without decisions.
