# Landing Page Anatomy

Use this to build or audit a page whose job is signup, lead, trial, purchase, call, booking, or visit.

## Do

- Match the page to the traffic source.
- Put audience, outcome, proof, offer, and CTA in the first screen.
- Use one primary CTA.
- Show proof before objections.
- Translate features into benefits.
- Handle objections before the final CTA.
- Keep mobile actions visible and usable.
- Measure page-level conversion and speed.

## When

- Before opening acquisition.
- Before paid traffic.
- Before launches.
- During relaunch audits.
- When source-specific traffic converts below baseline.

## How

1. Define source, intent, audience, and conversion.
2. Build the stack:
   - Hero.
   - Proof strip.
   - Problem.
   - Solution.
   - Benefits.
   - Objections / FAQ.
   - Risk reversal.
   - Final CTA.
3. Use [[conversion-copywriting]] for copy.
4. Use [[offer-pricing]] for offer and guarantee.
5. Use [[forms-signup-flow]] for forms.
6. Use [[social-proof-trust]] for proof.
7. QA mobile, speed, analytics, and first-run handoff.

## Watch

- Message mismatch from ad/post/search query to page.
- False floors above the CTA.
- Hidden pricing or unclear next step.
- Generic visuals.
- Slow LCP on hero media.
- Form drop-off.
- Mobile CTA obstruction.

## Avoid

- Multiple competing CTAs.
- Hero copy that names no audience or outcome.
- Proof-free pages for cold traffic.
- Long pages for simple warm intent.
- Reusing one page for unrelated traffic sources.
